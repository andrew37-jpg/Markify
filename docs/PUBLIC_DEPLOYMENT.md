# Публикация Markify для проверки с рабочего ПК

Статус: конфигурация подготовлена, сервис ещё НЕ опубликован. Реального URL пока нет.

## Подключения для развёртывания

Нужны доступ к Render и репозиторию GitHub с этим кодом. В проект добавлен `render.yaml`: Docker-сервис с постоянным диском для SQLite. Публичным будет адрес страницы входа; каталог, маркировки и управление принтерами остаются за авторизацией.

Конфигурация использует платный вычислительный ресурс `0.5c-512mb` и диск 1 GB. Ресурсы не созданы, списаний этим действием не инициировано. Перед созданием необходимо согласовать фактическую стоимость в аккаунте.

При развёртывании задаются `MARKIFY_BOOTSTRAP_ADMIN_EMAIL` и новый сильный `MARKIFY_BOOTSTRAP_ADMIN_PASSWORD`. `MARKIFY_SESSION_SECRET` создаётся хостингом. Учётные данные не помещаются в репозиторий. Сервер учитывает `PORT`, не запускает development reload.

База из локального архива не включается в Docker-образ. При первом запуске на пустом диске создаётся новый каталог; старые пользователи, принтеры и токены не публикуются. Если нужны существующие данные, сначала необходим отдельный согласованный перенос рабочей БД.

После запуска нужно проверить страницу входа, авторизацию, каталог, создание принтера и запросы агента по реальному HTTPS URL. Ссылку можно считать рабочей только после успешного развёртывания и этих проверок.

## Печать на рабочем ПК

1. Открыть опубликованный HTTPS-адрес, войти.
2. Добавить принтер: выбрать протокол, IP или системную очередь, размер и DPI. Сохранить показанный токен.
3. Установить актуальный Print Agent из этой же версии на компьютер рядом с принтером.
4. В `agent/.env` задать реальный URL в `MARKIFY_URL` и токен в `MARKIFY_AGENT_TOKEN`.
5. Выполнить `python agent/agent.py --check`, затем `python agent/agent.py`.
6. Отправить одну тестовую этикетку и сравнить бумагу с данными задания.

Принтер не требуется открывать в интернет: агент получает задания с сервера по исходящему HTTPS и отправляет их принтеру локально.

**Windows:** прямой LAN-вариант TSPL/ZPL/ESC-POS использует TCP. Существующий CUPS-вариант для USB рассчитан на macOS/Linux; Windows USB-spooler не реализован. До проверки USB на Windows нужно уточнить модель и добавить подходящий транспорт, а не обещать работу существующего CUPS-адаптера.
