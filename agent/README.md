# Markify Print Agent 0.10.2

Устанавливайте весь проект: агент использует модули `app/printer_adapters.py`, `app/label_render.py` и шрифты `app/fonts`.

Из корня проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-agent.txt
cp -n agent/.env.example agent/.env
```

Заполните `agent/.env`:

```dotenv
MARKIFY_URL=http://127.0.0.1:8000
MARKIFY_AGENT_TOKEN=токен-из-страницы-принтеров
MARKIFY_AGENT_POLL_SECONDS=2
```

Файл загружается автоматически. Настройки из окружения имеют приоритет. Не помещайте действующие токены в git или общий архив.

```bash
python agent/agent.py --check
python agent/agent.py
```

Запуск `python agent.py` из папки `agent` также поддерживается. `--check` не отправляет ничего на принтер, он проверяет только сервер и токен.

TSPL/Xprinter/TSC, ZPL и ESC/POS получают растровый макет с включённой кириллицей. Для CUPS/Атол/Godex требуется установленный системный драйвер и его очередь. Временный PostScript-документ передаётся команде `lp` и удаляется автоматически; диалога браузера, PDF и действий пользователя с файлом нет.

`raw9100` остаётся экспериментальным UTF-8-текстовым транспортом: он не является универсальным языком принтеров. Для обычной маркировки выбирайте язык модели или системный драйвер. ESC/POS здесь использует растровую команду GS v 0; её поддержку и автоотрез нужно проверить на модели.

Если связь оборвалась во время отправки, часть этикеток могла выйти. Агент не повторяет отправку автоматически; задание требует проверки. Потерянный ответ о завершении также не приводит к повторной отправке. На один принтер используйте один запущенный агент.

Старую версию агента нужно заменить вместе с сервером: теперь после захвата требуется `X-Print-Claim`. Не запускайте старый и новый агенты одновременно.
